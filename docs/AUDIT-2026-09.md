**A2-03** — `ProductPurchaseExperience` derives the active `variant` by

the CTA and show "combinaison indisponible" instead of falling back. Left as a finding —
logic is committed but the file is WIP.

`BETTER_AUTH_URL` and enforces an origin check on state-changing POSTs, so a browser at

`"Ce numéro de téléphone est déjà utilisé."`, but Better Auth swallows the message and
returns a generic `422 "Failed to create user"`. The client form's own `PHONE_REGEX` +
the DB `customer_phone_unique` constraint mean a real user usually sees a better message
or is stopped earlier, but an API caller (or JS-disabled client) gets no useful reason.

**A4-03** — `login-form.tsx` / `signup-form.tsx` / `compte/page.tsx` carry the parallel
